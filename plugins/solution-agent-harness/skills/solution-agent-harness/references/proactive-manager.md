# 主動派工與接續管理

只供本地 manager 管理已授權工作。worker 不因本規範取得派工、科研決策或跨 chat 管理權限。本文件補充管理判斷，不提供背景喚醒或持久排程服務。

## 授權與待辦

- 從會話與原任務交付物核對已承諾工作，再對照 publication journal 和回執。尚未發布的漏派項可能不在 journal；不要新增另一套共享佇列。
- 依整段會話的有效授權推進。使用者本輪詢問狀態不自動撤銷先前接續授權；若只授權查詢/討論、明確要求暫停或限定本輪動作，遵守其限制。
- 下一步符合既有授權便主動處理，不反覆請求相同許可。研究假設、樣本/切分、重訓或融合設計的新決定仍交給使用者；只阻塞依賴該決定的動作。

## 每次管理回合的接續責任

發布部分失敗、同 ID 回收成功、結果驗收、阻塞解除或管理連線恢復後，重新核對範圍內全部未完成工作。以目前持久狀態為準，不假設曾收到每個事件。

1. 對每項下一動作確認授權、完成條件、必要依賴、資源與正式 writer 條件。依賴須來自已批准任務或證據，不因同批/同主題就加上依賴。
2. 依正式入口處理所有可執行項；相依或寫入範圍重疊的工作序列化，獨立工作分別推進。同一 capsule 仍遵守既有 lease 協議。
3. 每項保存實際結果與原 IDs。單項錯誤不終止其他獨立項；共同身分、資料庫、權限或證據完整性故障則阻塞受影響項。
4. 回傳結果先驗收，再核對下一步。回合結束時，每項未完成工作須有運行紀錄、具體等待/阻塞條件，或本輪未派發的原因。manager 在線或 pending=0 不代表工作已處理完。

「可執行」須同時具備授權、有效輸入、依賴已滿足、可取得正式寫入條件，且無不確定提交。「運行中」須有原 command ID 與回執支持。「等待」記錄所需事件及既有監控/人工恢復路徑。「技術阻塞」記錄缺失與解除條件。「需科研決策」提出具體待決問題。「已驗收」須滿足原完成條件。

queued/ready/prepared/finished 是發布或執行狀態，不能直接取代上述管理判斷。queued 必須檢查；finished 仍可能只是 partial 回傳。尚未派發不能歸因為 worker 失敗。

## 原命令與新接續

執行、等待及恢復協議沿用 [remote-codex.md](remote-codex.md) 與 [SKILL.md](../SKILL.md)，不在此重定義。

- 回收原動作沿用原 task/work unit/command 身分；重試發布恢復原 publication、input 和 origin，不用新 ID 掩蓋不確定提交。
- 原命令已確認終態、必要 lease 已釋放後，真正的新授權接續使用同 task 的新 work_unit_id。登記成功但 capsule 收尾衝突，先完成原命令收尾，再接原 publication，不重做登記副作用。
- 原提交是否發生不明、lease 過期或 manager 失聯，先查原命令/程序及 owner 證據，不直接重派。入口已用過有限重試預算，不再疊加 manager 重試迴圈。
- 沒有可執行項後交還既有事件等待；遵守主 skill 的 suppress_model_continuation/manual-resume 規則，不以本規範建立輪詢或模型心跳。

## 管理輸入與驗收

每輪只帶本輪動作/問題、新證據引用與 hash、完成條件、必要 IDs，以及授權差異。固定規則引用可實際讀取的版本。問題摘要、Artifact Clipboard 及短 Goal 規則以主 skill 為唯一來源。

回覆送出、答案保存、worker 確認是互動證據；原科學條件仍須獨立驗收。回報已接續工作、各項阻塞及解除事件/決策，不把一次互動成功稱為科研完成。
