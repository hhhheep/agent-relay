# HF-002 managed-document handoff contract

Authorized scope: complete the existing local-file draft/packet/review/CAS/read-back path, preserve ResearchFlow ownership, add isolated regressions and candidate CI before engineering push. Baseline: 755d4ef. No live destination, installed configuration, new scheduler, database or MCP tool.

Owners: report Writer already emits publication_packet.json; ArtifactStore owns immutable draft/packet/review evidence; ArtifactApplyEngine owns plans, target CAS, receipts and restart recovery; TaskCapsuleStore owns existing writer exclusion. publication_registry and task_md_sync configure immutable worker input snapshots, not authoritative report publication, and must not be repurposed as a second document database.

Extension: existing artifact_apply string mode gains publication. Existing materialize/compose/patch requests and serialized plans retain their shape. A publication plan uses the same ApplyPlan directory/candidate/diff/receipt with mode=publication; old strict readers reject this mode instead of bypassing review after rollback. New readers retain old plans. No live migration, exact runtime/workplace pair gate relaxation or cross-version claim. Revert source without consuming new publication plans on an old runtime; immutable draft artifacts remain recoverable.

Plan requires an explicit task-bound managed_markdown declaration with exact relative draft/target, direction, draft/review/publish owner attestations, scope and accepted destination hash (null only for a new target), plus an existing Writer v1 packet artifact. Source/destination/hash/protocol must agree; ResearchFlow packets remain with their GET/SHA/PUT owner and fail closed in this local publisher. No credentials or HTTP client is added.

Draft planning writes only existing immutable artifacts and apply-plan evidence, taking no writer lease. Review attests the exact plan, diff, declaration and candidate hashes through a scoped immutable artifact; this records the trusted controller's review, not a new identity authentication system. Commit acquires the existing exclusive writer lease; busy tasks retain their plan/review for explicit later retry, with no scheduler or force takeover. Published and verified are distinct: a read-back mismatch retains the receipt and reports conflict without republishing.

Section publication reuses existing md_sync managed-block parsing and preserves all bytes outside explicitly named SYNC blocks. Full-document replacement is only for a declared local report artifact; it does not authorize wholesale ResearchFlow record replacement. Tests will cover actual MCP entry, packets, exact review binding, ownership/scope mismatch, stale SHA, active lease deferral, immutable evidence, replay/restart and target read-back drift. Live ResearchFlow and new-runtime Linux/M1-M4 acceptance remain outside this isolated source verification.

## Verified local workflow

`artifact_apply(mode="publication")` now supports plan, separate review metadata storage, inspect and commit using the same plan ID. No new top-level MCP tool or top-level tool schema fields were introduced. Plan/review do not acquire a writer lease; inspect derives status from existing plan/review/receipt and current target bytes, not a new status database. Publication commit is serialized with the existing TaskCapsule file-lock primitive, and generic commit cannot bypass publication review/read-back.

The exact v1 packet emitted by the real report Writer with a synthetic provider is consumed end-to-end; Writer still never edits authority. Full-document or explicitly marked section candidates use the same ArtifactStore and existing md_sync parser. Approved base SHA and scoped destination are checked before side effects. Review binds plan, diff, declaration and candidate, and an approved review cannot be rebound to another review artifact for that plan. Owner names are trusted-controller attestations under existing task/host authorization, not a new authentication layer.

The 30 new tests include real in-process MCP plan/review/commit/replay, a real Writer-generated packet, busy-writer deferral with no takeover, restart recovery, receipt/lease-finalization interruption, concurrent retries, rejected/mismatched review, wrong task/publisher, explicit new-target alignment, stale SHA, expired plan, destination scope revocation, section escape and post-publication read-back drift. Existing artifact and Writer regressions remain active. No paid provider requests were made.

Boundary: ResearchFlow's packet is intentionally rejected by the local-file publisher; its record owner and GET/SHA/PUT/409 protocol remain unchanged. No ResearchFlow client or replacement publication service has been added. Live record publication and current runtime Linux/M1-M4 are NOT RUN. HF-002 historical on-site acceptance therefore remains open even though the local-file source handoff is implemented.

The separate review step also persists directly into the same ArtifactStore while an existing writer is active; no review file has to be written through that writer. Inspect computes reviewed_waiting_for_writer from the existing review and capsule lease. Tests additionally cover missing accepted alignment, source read scope, the existing Writer uppercase-SHA form and interruption after replace before receipt.
