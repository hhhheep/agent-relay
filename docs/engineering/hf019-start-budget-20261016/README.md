# HF-019: bounded SSH startup admission

User-authorized scope: protect new managed-launcher SSH transport starts while preserving independent MCP stdio per chat. Baseline ce02264. Ordinary source protection plus a local transport-state/configuration boundary extension; no deployment, installed cache, SSH config, live state, task replay, pool, broker or automatic reconnect loop.

Owner: solution_agent/harness/ssh_admission.py is the single editable admission authority. The release-owned remote launcher, orchestrator SSH/SCP adapters and profile lifecycle are its direct consumers. The profile materializer copies that exact helper into the standalone plugin; no second editable runtime is maintained. Profile plugin materializer must preserve/copy the helper and allow bounded admission waiting. Existing command/receipt/lease/workplace/protocol gates remain remote-owned. This compatible source extension also covers existing maintenance transports, without changing their task/receipt APIs. It introduces no core dependency on plugin scripts. Rollback reverts these consumers and the materializer together; existing task state remains unchanged, and the local ledger can be left unused.

New state is a per-local-user SQLite startup ledger under the existing Codex local state namespace, shared across control roots. It stores hashed endpoint/context keys, random attempt IDs, timestamps and diagnostic categories only; not hostnames, identity paths, private keys, raw stderr or credentials. Atomic short transactions reserve starts before spawn. No database lock lasts for SSH lifetime. Crashed processes consume only expiring rate entries, never permanent ownership.

Target verification uses ssh -G with the same managed options and bounded local configuration evaluation, then bounded address resolution. Both normalized effective HostName/port and all resolved address/port keys are reserved atomically; aliases/profile changes resolving to the same endpoint share a budget. Different users/identities still share endpoint start rate, but authentication backoff is credential-context-specific and host-key backoff is trust-context-specific. Only configuration values and file metadata are hashed; key contents are never read. This is local protection, not a security boundary against a local user changing code/state. DNS aliases with shared resolved addresses share protection; arbitrary remote infrastructure is not inferred.

Opaque ProxyCommand and ProxyJump routes fail closed with an unsupported-target diagnostic rather than silently bypassing a direct-endpoint budget. Extending admission to their intermediate endpoints needs a separate explicit route contract. No proxy settings are changed. Alternative alias-only counters were rejected because aliases bypass them; an exclusive live connection lock was rejected because it breaks multiple chats. No multiplexing framework is introduced.

Defaults: at most three starts per endpoint in ten seconds; bounded admission wait 45s; transient failure backoff 2s exponential capped at 30s plus bounded jitter; after three consecutive network/unknown-transport failures, a 300s circuit cooldown stops further starts; authentication/host-key diagnostic cooldown 300s with immediate stop rather than sleeping/retrying. Unknown exit 255 is not called authentication failure. Remote application failures are scoped to route/context rather than all clients. Every guarded entrance explicitly uses BatchMode=yes, ConnectTimeout=10 and ConnectionAttempts=1, so configured internal connection retries cannot silently bypass one admission. No identity or trust policy is weakened. One launcher invokes SSH at most once; later host relaunches must pass the persisted ledger. Old legacy locks/cooldowns are untouched. Long-established session closure is not counted as a startup failure. Wall-clock reversal/future state is normalized to bounded windows, not permanent denial. Corrupt/unavailable state fails closed visibly. Lifecycle HarnessPort must pass the generated positive bounded startup timeout to the existing SDK handshake rather than abandon admission at its default 60s; old configurations keep the existing default. This directly consumes the materializer setting, without adding reconnect logic. Generated managed plugin startup timeout becomes 90s to accommodate admission, local resolution, ConnectTimeout=10 and MCP initialization.

Validation uses fake clocks, isolated state and synthetic SSH subprocesses only. No school endpoint or credential is probed. The school ban's cause/threshold is unknown; defaults are not claimed to match it. Arbitrary shell SSH/SCP and external scripts cannot be constrained by this library; this is not a machine-wide firewall. Explicit maintenance remains available through the guarded existing entrances.

Primary SSH contract: https://man.openbsd.org/ssh.1 (-G evaluates Host/Match then exits; exit 255 indicates an error, not a specific authentication cause). Host/Match evaluation may invoke locally configured directives; no real SSH configuration is evaluated in tests.


Routing audit: the formal MCP server does not call the legacy SSH adapters. Lifecycle HarnessPort sends dispatch/status/recovery through its existing MCP client and throws harness_reconnect_required after disconnect; it does not create a replacement client or raw SSH fallback in call(). Existing disconnect tests preserve original command IDs and reject changed runtime identity. Source skill/reference guidance now explicitly forbids rapid client reopening and automatic transport fallback on throttling, timeout or unavailability. Guidance constrains agent behavior; it cannot intercept arbitrary shell commands. No global skill, installed plugin or SSH configuration was changed.

Coverage: managed launcher, profile_deploy inspection/probe/upload/snapshot/download/deploy entry points (including audit_profile_upgrade via _ssh_python), and orchestrator run_ssh/open_ssh_stream/scp_to_remote/scp_from_remote. A stream watcher observes process exit without consuming the caller's merged output; an unclassified exit 255 gets unknown_transport backoff, not an authentication assertion. Only this local OS user is coordinated; other machines/users behind the same public IP and uninstrumented external tools remain outside the guard.

Deployment remains NOT RUN. No arbitrary SSH configuration weakening, existing connection termination or remote service restart is part of this source repair.
