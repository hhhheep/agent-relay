# HF-017: ordinary command completion is a work-unit decision

Base `41dc00e`; branch `codex/hf017-work-unit-review-20261015`. Ordinary lifecycle fix in TaskCapsule/terminal collection and the existing explicit maintenance finish helper. Existing field evidence is private and unchanged; no historical task is closed.

Before repair, successful ordinary commands retained capsule lifecycle ACTIVE after their writer lease ended, lacked a separate unit disposition, and rejected follow-on units without explaining whether execution remained. A real-runner regression reproduced the missing disposition. The existing explicit maintenance finish also allowed a capsule carrying an unresolved wait; it now refuses that transition.

After a terminal ordinary writer result is collected with no remaining writer leases, the owned unit retains its ID and transitions by CAS to the existing REVIEW_REQUIRED lifecycle value. This is an owner finish/continue decision, not scientific acceptance. A same-unit continuation acquiring a writer lease returns to ACTIVE. Explicit maintenance finish reconciles the original terminal command, closes the unit and permits a following unit; unresolved waits, active writers and unknown/lost outcomes do not authorize finish. Persistent/TUI or sequential units remain owned unless explicitly finished.

The tool returns a separate work_unit summary: command state, unit decision state, current writer-lease count, external_resources=unknown and research_acceptance=not_assessed. A different-unit conflict names the retained ownership and decision instead of suggesting an occupied execution slot. No claim is made about detached processes, GPU/CPU allocation or research completion. No new tool, scheduler, process scan or state format is introduced. Optional output stays within the existing arbitrary-dict tool response; exact-pair activation remains required. The tool-description/source hash must be regenerated by the existing builder before any installation.

No assertion is weakened. Current publication/provenance and diff checks pass; immutable source-map history is retained.
